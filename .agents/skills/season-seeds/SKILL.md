# Season seeds (weekly plants)

Mirror of `weekly-visitor` for plants. Paths relative to `models/`. Rules: SPEC.md Garden ("When a plant finishes", "3D plants, one per plant"). Each plot (habit) grows one plant at a time; when it blooms or dies it shows that for a week, then the next plant goes in. Every plant gets its own species, made here, just in time. No stock is made ahead.

When: every week, after the visitor (`weekly-visitor` step 1c), or by hand.

No spoilers (weekly-visitor "No spoilers"): messages call each plant by its plot and gen, never its species, name or look.

0. Preflight `./setup.sh --check`.
1. Inputs: `checks/game_status` `value.garden` (`season` = calendar season name, `biome`, `needs`; else ask). `needs` = `[{plot, habit, gen, rarity, mutated, biome, sown}]`: one entry per plant with no model yet. Skip an entry whose roster plant (`plot` + `gen`) already exists. Empty → report "no plants needed" and stop. Also read that biome's `biomes.json` entry and the roster's plants.
2. **One subagent per entry, in parallel** (Agent tool, `model: "sonnet"`, all spawned in one message; AGENTS.md "Subagent models"). Each subagent owns one plant end to end and gets only ids and paths: the entry (`plot`, `habit`, `gen`, `rarity`, `mutated`, `biome`, `sown`), the season, and this skill's path. Its brief: read this skill and the per-plant chain below, start its own ledger, run the chain, and return `{plot, gen, id, outcome: "pass"|"below_bar"|"quarantined", ledger: <ledger.py status>, retro: [..]}` with no species, name or look in the text it returns. The machine caps concurrent Blender jobs itself (`shared/tools/slots.py`, held by every `build.py` and `verify.sh`; slot count `LB_BUILD_SLOTS` or half the cores), so spawn every entry at once: a plant waiting for a slot has that time credited back to its ledger (`minutes_queued` in `ledger.py status`), so its 30 minutes measure its own work. Subagents never touch shared files: `roster.json`, git and the artifact belong to the orchestrator (step 3b).
   **Per-plant chain (one subagent).** Start the ledger when the subagent starts: `python3 models/shared/tools/ledger.py start plant-<plot>-g<gen> --rounds 4 --minutes 30` (the ledger enforces it, never count in your head).
   `plant-brief` (biome, rarity, habit name, season, plot, gen) → `model-build` (`blender -b --factory-startup --python shared/blender/build.py -- plant/specs/<id>.json --run <run_id>`; also rigs, animates, exports) → `plant-grow` (check + fix loop) → `model-verify` (`VERIFY_RUN=<run_id> shared/tools/verify.sh <id>`: shared gates + `plant/qa.py`; a fresh judge panel recorded in the ledger, verdict from `judge_verdict.py`. The subagent spawns its own judge subagents as model-verify says) → `model-ship` steps 1–2 only (optimize, re-check the shipped copy, wrap `assets/<id>-glb.js`), then return the roster entry it would add (per `plant/CONTRACT.md` Shipping, with `plot`, `gen`, `habit`, and `below_bar` when below the bar) instead of writing `roster.json`.
3. After a judge-panel PASS the subagent runs model-verify "Polish rounds". Retries/fallbacks as in weekly-visitor: route fix notes to the step that owns them. Fallback: drop the accessory / novel parts and ship the plain species on the closest proven generator (`stem_bloom`, e.g. `plant/specs/mermaids_cup.json` reshaped). Budget spent without a PASS → ship the best attempt below the bar (weekly-visitor fallback 2: `ledger.py best <run> <id> --below-bar`; automated gates must pass). Only when no build passed the automated gates → quarantine `out/quarantine/<id>/`, move the spec to `plant/specs/quarantined/<id>.json` (`git mv` when tracked), and return `quarantined`. The plot keeps its SVG species (it has no model yet); next week's run tries again (the entry stays in `needs`).
3b. **Orchestrator, once every subagent has returned**: append each returned roster entry to `roster.json` `models[]`, then model-ship steps 4–5 once for all of them (one commit, one publish; weekly-visitor's visitor rides the same publish). A subagent that dies or returns nothing counts as quarantined for the report; its ledger file still says how far it got.
4. Report (orchestrator, from the subagents' returns): plants shipped (plot, habit, gen, rarity, passed or below bar), gates, ledger status, anything quarantined. No species, name, look or accessory. model-ship publishes the live board (pre-approved; AGENTS.md Publish).
5. Retro (AGENTS.md "Improve as you go"): merge the subagents' `retro` lists; one line per problem this run hit, and the fix to this skill, plant-brief, a gate or a tool, made in the same commit.

page-test runtime for plants: `test.html#eco` (lifeboard-setup), a plot of the new species renders all five stages in the Garden card (garden package `plotSVG`), no console errors.
